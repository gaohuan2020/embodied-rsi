# 从零验证搬运入盘的 RSI 自我改进

## 研究问题

从原始 RSI 决策头开始，仅通过自主完成任务的轨迹训练，候选在完整任务上的成功率是否随轮次提高？通过发布门槛后的实际部署版本是否也提高？两者分别报告。

原假设：没有可靠提升，或曲线存在持平／退化。不会把曲线强制改成递增，也不会因为训练 loss 下降就接受模型。

## 重置与基线

清除本项目旧采集轨迹、数据、SQLite、作业、微调检查点、部署指针、旧公开报告和截图。初始模型为 RSI-Jev `v1.0-0.8b`，revision `f9248caceb89caf2e6c968ea33bf0d6eb7f957b0`，统一 FP32。原始基线不读取旧微调权重。研究命令拒绝已有训练／部署历史的目录，重复实验必须使用全新 artifacts 目录。

重置后的冷启动预试验：seed 0–11，12 次模型随机探索，1 次完成。只把这次真实成功轨迹计入可用数据。教师初始化未运行。

## 冻结条件

- MuJoCo / Franka Panda，skills-v1 九技能候选，最大 20 步。
- 仅 transfer：物体进盘、稳定支撑、松开夹爪并撤离。
- 源位置以 (0.43, -0.17) 米为中心，±0.025 米随机；目标 (0.43, 0.18) 米固定。
- 3 轮，各 30 局采集、100 次 head 更新、10 个开发任务、90 对新发布场景。
- 正式默认 90 个最终审计场景；本次快速试验设为 30，最终区间与样本不足限制明确报告。
- 配置在实验开始写入 protocol.json 并计算哈希，结束验证未修改。

## 每轮步骤

1. 用原始或已通过发布的版本探索，保存全部完整成功和失败轨迹，包括输入、候选、概率、动作、终端判定、场景与版本。
2. 汇总本轮及之前的自主成功轨迹，过滤失败动作，生成不可变数据集和校验和；仅 transfer 数据可进入此实验。
3. 冻结文本塔、缓存真实输入特征，训练 RSI head。记录 loss、梯度、样本量；每 25 步和最后一步做完整任务开发评测。
4. 保存开发完成率最高的检查点；风险指标用于同分选择。开发退化时保留早期版本，即使其为第 0 步。
5. 在 90 个新的同初态场景上与当前版本配对，统计完整成功率、提升区间、碰撞、失抓与拒绝。
6. 全部门槛通过才实际加载、预热和切换。未通过就保留当前版本，下一轮继续从被接受的版本采集。

没有成功数据时跳过训练并如实报告，不能用教师轨迹补成“模型自主成功”。

## 场景与模型隔离

SQLite 每次事务预留独立 30,000 种子：训练／开发／发布各 10,000。最先单独预留最终审计池，再预留各轮数据空间；审计集不进入梯度、开发选模和部署门槛。

候选与父版本使用同一冻结 tower 的两个独立 head 做发布比较，保持精度与候选顺序。线上推理同样为 FP32；实际 GPU 对缓存前向、完整前向、线上推理和重排后的前向分别验证。候选文件与评测对手都绑定哈希；变化则拒绝报告／部署。

## 统一审计与结论

所有轮次训练和发布决策完成后，再对 V0 与所有候选使用**同一组**最终保留场景，评测实际保存后重载的模型。审计结果不触发部署。

同时画两条线：蓝色为各轮候选，绿色为各轮实际部署版本。若某轮未晋级，绿色保留之前模型的成绩；不会用候选的较好成绩冒充已部署。

- 每一相邻轮都严格大于上一轮，才报告“候选完成率逐轮上升”。
- 部署线同样判断；持平不算严格上升。
- 另报告预先声明的最终候选对 V0 的配对区间。30 个审计场景只作小规模验证，不能代替 90 对发布门槛。
- 若后续更改控制器、随机目标范围或测试预算，建立新实验，不混入同一条曲线。

## 输出

`protocol.json`、完整采集／审计轨迹、成功数据 manifest、训练指标与 loss、每轮独立报告、真实部署记录、最终 report.json 与 study-latest.json。dashboard 同时显示运行进度、成功数据、损失、门槛和最终两条曲线。
