# 有状态代码策略对照实验

借鉴 [Embodied Turing Machines](https://arxiv.org/abs/2610.12369) 的显式状态、失败恢复与代码策略思路。第一版实现策略对照，尚未实现 coding agent 自动生成、筛选和合并策略修改。

实验仅覆盖 `transfer`。四种策略使用相同结构化观测、阶段菜单、航点生成、IK 与物理执行器：

| 策略 | 决策与恢复 |
|---|---|
| `code` | 依据当前几何、夹持与支撑状态选择技能；每局最多两次恢复 |
| `code_no_recovery` | 相同正常规则；首次检测到执行失败便结束，作为恢复消融对照 |
| `rsi` | 原有模型独立选择技能，无代码策略恢复钩子 |
| `hybrid` | 代码处理动作前提和恢复；存在多个合法选择时，模型在原始菜单上评分，再过滤不合法动作 |

代码记录阶段、抬升证据、重试计数、下一恢复动作和失败原因。空抓后重新对准；失抓后清除旧抬升证据并重新获取；持物动作被拒时保持夹爪闭合。每局重置这些状态。策略及反馈接口均不读取教师标签、场景种子、未来分支收益或仿真成功真值。

## 运行

无需 GPU 的恢复对照：

```bash
MUJOCO_GL=egl .venv/bin/embodied-rsi --artifacts artifacts/code-study \
  code-study --episodes 90
```

加入已有 RSI 检查点及混合策略：

```bash
MUJOCO_GL=egl HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  .venv/bin/embodied-rsi --artifacts artifacts/code-study code-study \
  --checkpoint artifacts/runs/self-train-20261009-164902-ba1977/checkpoint \
  --rsi-python "$PWD/.venv-rsi/bin/python" --episodes 90
```

检查点参数必须是本地 RSI-Jev 目录；拒绝将 Compact 检查点标记为 RSI 对照。实验读取模型，不修改检查点。默认从 20,000,000 之后事务预留新种子，实际评测种子写入冻结协议；检查模型训练／开发范围及数据 manifest，拒绝重叠。失败或取消的种子区间也不会复用。默认启用阶段提示，可以用 `--no-staged-prompts` 开一项独立对照；本实验显式配置优先于环境变量。

## 两类场景与成功定义

`normal` 使用现有 `workspace-random-v1` 源／目标位置随机化。`missed-grasp` 使用同一分布，但在首次闭合请求时，执行器故意保持夹爪张开一次。预演分支不消耗或重复记录真实故障；每种策略收到相同初态和相同故障规则。记录实际触发故障的局数及这些局的完成率，避免把没有尝试闭合的失败局当作已恢复。

两类结果分别报告，不合并为同一完成率。成功统一使用 `strict_grasp_v1`：须实际抓住、抬升、搬运、释放并撤离；发生失抓或危险接触则不算成功。因此，失抓恢复逻辑虽然存在，本协议不能用“掉落后重新抓起”证明完整成功。正常场景、故障场景和不同成功定义也不能接到旧学习曲线上。

## 报告与数据边界

每次运行生成：

- `runs/code-study-*/protocol.json`：种子、配置、源代码及上游物理／规划文件哈希、检查点哈希。
- `episodes.jsonl`：全部逐步输入、候选、决策、恢复反馈、真实物理结果与故障记录。
- `report.json` 与 `code-study-latest.json`：各策略完成率、动作数、模型调用数、决策延迟、风险，以及配对提升区间。

模型启动与预热耗时单独报告，不计入逐步决策延迟。逐步延迟包含 Python 策略调用／模型 RPC，不包含物理执行；整局决策与执行耗时另行统计，不含新场景初始化。代码策略与混合策略都共享已有执行器，零模型调用不意味着零仿真成本。

复用现有配对 bootstrap 和发布门槛计算作为诊断，样本不足 90 对时不会通过门槛。报告不能直接部署代码策略；任何结果都不切换现有模型。接近 100% 的完成率也可能无法满足原有提升 5 个百分点的要求，成本收益需要另立预先声明的实验协议。

本次轨迹均标记 `data_role=evaluation_only`，成功回放入口拒绝导入。即使去掉该标记，`code`、`code_no_recovery` 和 `hybrid` 来源也不能冒充模型自主成功。后续若训练 RSI，应另行采集代码示范、保留来源，并建立监督初始化实验。

## 2026-10-14 实测

`code-study-20261014-163338-11033c`：四种策略、两类场景各 90 个初态，共 720 局。初态种子为 20,050,000–20,050,089，最大 30 步；启用同一阶段菜单，代码／混合策略最多两次恢复。模型为现有已发布 RSI 检查点 `self-train-20261009-164902-ba1977`，SHA256 为 `bac7fe5ac1302a8e7822182c1744773630379875587560c7920f268a7f341f61`。没有进行训练或候选选模。

| 策略 | 正常完成 | 故障后完成 | 正常平均动作数 | 正常平均模型调用 | 正常平均决策与执行耗时 |
|---|---|---|---|---|---|
| 代码策略 | 90/90 | 90/90 | 8.00 | 0 | 1.95 秒 |
| 失败即停止对照 | 90/90 | 0/90 | 8.00 | 0 | 1.95 秒 |
| RSI | 90/90 | 89/90 | 11.67 | 11.67 | 3.31 秒 |
| 混合策略 | 90/90 | 90/90 | 8.60 | 5.60 | 2.52 秒 |

所有策略均无碰撞、失抓和动作拒绝。故障场景中，每种策略均实际触发了 90 次首次闭合失效。代码与混合策略检测到空抓并重试；原始 RSI 也能在大多数场景下恢复。失败即停止对照在发现空抓后直接结束，因此它的零完成率仅用于验证恢复流程的作用。

正常场景中，混合策略减少约 52% 的模型调用；代码策略无需模型调用，平均决策与执行耗时比 RSI 低约 41%。这是本机当前推理环境的实测，不能代表优化后模型的性能。RSI worker 在本次环境中提示线性注意力等算子使用 PyTorch 参考实现。故障场景代码／RSI／混合策略平均耗时分别为 2.24／3.32／2.89 秒。

RSI 的唯一失败为故障场景 seed `20050055`：物体已被抓取、抬升、搬运并释放到目标，但模型在随后反复选择 `grasp → release`，用尽 30 步预算，没有撤离。同一初态下，代码策略与混合策略根据已放置、已释放的状态选择撤离并完成任务。全部代码在正式运行期间保持冻结，没有针对这个失败修改策略。

故障场景中，代码／混合策略相对 RSI 的完成率提升均为 1.11 个百分点，95% 配对 bootstrap 区间为 [0, 3.33] 个百分点。未达到原有提升 5 个百分点和区间下界大于 0 的门槛；当前证据支持执行效率收益和具体恢复案例，不能证明总体完成率可靠提升。90/90 也不表示总体必然成功。两类场景结果没有合并进旧学习曲线。

完整数值与冻结协议见 [code-policy-study.json](results/code-policy-study.json)。本地逐步轨迹和本次代码快照位于 `artifacts/code-study/runs/code-study-20261014-163338-11033c/`，协议 SHA256 为 `4ea180e27f4e532868530a56aea65012241c10d0dd7f005b304da2ace67e383e`。

最终验证：Ruff 与差异空白检查通过；pytest 56 项通过、1 项跳过。跳过项是主 CPU 环境未安装 PyTorch 的旧参数快照测试；本次真实 RSI 对照在独立的 PyTorch／CUDA 环境运行。新增测试覆盖真实空抓恢复、每局状态重置、持物拒绝后的恢复、候选顺序、混合动作过滤、评测数据隔离、种子泄漏和源代码变化拒绝。

## 后续扩展

下一阶段可在独立开发场景中分析失败，提出策略代码候选修改，先检查动作前提与状态转换，再在新场景配对评测后接受改进；最终保留集只在全部修改结束后揭示。运行中的策略代码保持冻结。现阶段没有自动代码迭代的效果证据。

本项目仍读取仿真物体状态，并使用仿真碰撞预演。第一版没有复现论文的 RGB 感知，也不证明真机或新任务泛化。
